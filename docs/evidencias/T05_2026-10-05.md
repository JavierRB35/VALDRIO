## Reauditoría B01/B02/G02 — corrección posterior

Commit de código inicial: `076cc62800a0f284e79547e1de73eb399be5903a`.

**B01.** `StudyWorkspaceViewModel` ya no espera a `Reload` para reconocer el resultado de una escritura confirmada. Crear, guardar, cerrar/reabrir y capturar pasan por `ConfirmedCommitRefresh`: el estado/receipt confirmado se aplica primero y la relectura se intenta después. Si falla, el resultado permanece visible, se registra el fallo y el estado de UI indica que la escritura quedó confirmada pero el refresco está pendiente. Un refresco posterior sustituye `Current` por la revisión persistida solo cuando no existe una edición pendiente.

**B02.** `PresentationPreferencesPersistence` captura exclusivamente `IOException` y `UnauthorizedAccessException` del adaptador de almacenamiento. El cambio de preferencias ya aplicado en memoria continúa notificándose a suscriptores posteriores. `JsonUserPresentationPreferencesStore` usa temporales únicos y los limpia incluso si falla la sustitución. Se añade `Preferences.SaveFailed` EN/ES.

**G02.** `.github/scripts/Verify-Windows.ps1` exige un repositorio limpio antes de comenzar y al terminar, comprueba que HEAD no cambió y crea/valida `artifacts/acceptance-build.json`. El manifest fija `SourceCommit` y SHA-256 del ejecutable Desktop, Runner DLL, assembly de tests y TRX. `-UseExistingBuild` falla si el manifest no existe, pertenece a otro commit o cualquiera de esos hashes difiere. El receipt final incorpora los mismos hashes y el hash del propio manifest.

Regresiones añadidas: **5 métodos** en `T05RecoveryRegressionTests` (commit confirmado antes de refresh fallido/normal; persistencia IO; acceso denegado; limpieza de temporal tras sustitución fallida).

Limitación de esta corrección: el contenedor usado para publicarla no contiene `.NET SDK` ni `pwsh`. Por tanto no se registra build, ejecución MSTest ni ejecución PowerShell sobre este HEAD.
