# T09 — Reparto primario con trazabilidad

Entrega propuesta en `feature/t09-primary-allocation-20261008`, basada en
`main@6f99e592`. La [ficha R0](../../specification/v0.4/tareas/T09.md) y
CM04/CM05/CM16 siguen siendo normativas.

## Implementado

1. **Entrada congelada:** `PrimaryAllocationService.Calculate(AllocationStudySnapshotInput)`
   consume snapshots v7 con partes, versiones publicadas de claves, reglas, importes
   funcionales y procedencia. La misma operación acepta
   `AllocationWorkspaceSnapshot` para el borrador real de WPF.
2. **Hechos adjudicados:** para cada parte `AllocationPool`, resuelve asignación
   absoluta, manual o regla exacta/prefijo. Reutiliza `AllocationKeyRules.Preview`
   de Calculation (sin fórmula duplicada en XAML, SQL ni Reporting). Emite
   `PrimaryAllocationFact` con ResourceId, PartId, Account, NodeId, PoolId,
   KeyVersionId, RuleId, pesos, participación, bruto, corrección numérica,
   redondeo, importe publicado internamente, comportamiento, capa y capacidad.
   La parte se adjudica junta a `10^-8`, incluidas negativas; no se convierte
   a céntimos de visualización en esta etapa.
3. **Conciliación y consulta:** diferencias por parte, descomposición de recurso
   (directo + pool + excluido + pendiente) y totales agrupados estrictamente desde
   los hechos adjudicados. `ByResource` y `ByNode` devuelven proyecciones
   ordenadas. Errores y pendientes tienen diagnóstico estructurado y bloquean
   `IsComplete`, aunque el neto global parezca correcto.
4. **UI y demo:** sección de consulta de resultados en Claves y reglas, con
   estado y textos ES/EN. `Valdrio.Runner --primary-snapshot <receipt.json>
   [output.json]` lee un recibo canónico real, imprime/exporta JSON
   CanonicalExchange invariante, con exit code 0 balanceado, 4 incompleto o
   3 archivo/contrato inválido.

## Límite deliberado

Esto es una **proyección en memoria**, no una publicación durable de ejecución.
T11 es responsable del RunId, IRunStore y publicación transaccional. Las claves
secundarias se congelan y validan en T08, pero el solver pertenece a T10.
Una parte pendiente nunca se convierte silenciosamente en un destino.
El tratamiento de capacidad se etiqueta y se comprueba para el propietario
específico, **no** se calcula una absorción ociosa con D04/D05 sin aceptar.
El selector mostrado en UI es de lectura; las ediciones siguen en la pantalla T08.

## Puerta de aceptación

Pruebas T09 añadidas para archivo SQLite real, snapshot capturado, multidosis,
negativo a ocho decimales, conservación por fuente y ausencia de regla.
La verificación de referencia sintética no ejecuta C#.
Pendiente compilar y ejecutar pruebas .NET 10, runner sobre archivo y recorrido
WPF Windows: registrar resultados antes de declarar la tarea cerrada.
