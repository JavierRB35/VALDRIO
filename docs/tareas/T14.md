# T14 — Actividad y capacidades por pool (guía de desarrollo)

**Edición R1 · Estado: documentación UX acordada, implementación pendiente.**

## Antes de implementar

1. Leer la [ficha canónica T14 v0.4](../../specification/v0.4/tareas/T14.md) y el contrato metodológico CM08 (datos físicos por pool, unidad, periodo y fuente).
2. **Lectura obligatoria:** [T14 — capacidad normal asistida, anomalías y microayudas de cada campo](../directrices/T14_CAPACIDAD_NORMAL_ASISTIDA.md). Esta es la directriz operativa de interfaz y requisitos de aceptación del propietario.
3. Aplicar [USABILIDAD](../directrices/USABILIDAD.md), [sistema visual V1](../diseno/SISTEMA_VISUAL_VALDRIO_V1.md) y [AGENTS](../../AGENTS.md).

## Resultado esperado

Una sola tabla de actividad/capacidad por pool. Los campos básicos son centro/actividad y unidad precargados, capacidad normal editable, actividad real editable/importable, utilización calculada y diagnóstico comprensible. Periodo y procedencia deben estar accesibles en contexto. Las capacidades práctica y teórica son ampliaciones visibles a petición del usuario.

La edición de capacidad normal abre opcionalmente «Cómo calcularla», con tres opciones: histórico representativo, calendario operativo o cifra declarada con justificación. Cada opción explica **qué significa cada campo, qué introducir, cómo se obtiene y para qué sirve**, con ejemplos explícitos. La propuesta vuelve a la celda original solo después de ser revisada y adoptada; cancelar conserva el valor anterior.

Se conserva dato bruto, fuente, calidad, periodo, unidades, comparabilidad, versión y justificación de periodos excluidos. **No eliminar anomalías automáticamente, no inventar datos, no transformar presupuesto o actividad real en normal sin decisión documentada**.

No se implementan tarifas, valoración económica ni se aprueba D04 por esta tarea.

## Subentregas sugeridas

1. Datos físicos por pool y tabla básica con ayudas ES/EN y guardado/auditoría.
2. Asistente opcional de capacidad normal (tres métodos), sin duplicidad de campos.
3. Revisión de anomalías y coherencia entre unidad, periodos y calendarios; importación y aceptación real de uso.

## Comprobación de terminación

Además de las pruebas de referencia T14, realizar una prueba de comprensión con un analista no desarrollador: debe completar una actividad con normal/real, comprender diferencia entre normal/práctica/teórica, distinguir real cero de dato ausente y justificar una referencia histórica con una baja excepcional sin ayuda oral.

**Protección de costes:** no activar ni ejecutar GitHub Actions sin autorización expresa. Documentar y probar localmente en Windows cuando comience implementación.
